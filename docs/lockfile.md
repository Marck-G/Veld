# Lockfile (`veld.lock`)

The lockfile pins resolved dependency versions with integrity checksums, ensuring reproducible builds.

## Format

`veld.lock` is a TOML file:

```toml
[metadata]
generated_by = "veld 0.1.0"
generated_at = "2024-01-15T10:30:00Z"
manifest_hash = "a1b2c3d4e5f6..."

profile_hash = "f6e5d4c3b2a1..."

[[package]]
name = "fmt"
version = "10.2.1"
repository = "https://github.com/fmtlib/fmt.git"
commit = "abc1234567890abcdef..."
artifact_id = "fmt"
required_by = ["root"]
content_hash = "deadbeef..."
path = null

[[package]]
name = "spdlog"
version = "1.12.0"
repository = "https://github.com/gabime/spdlog.git"
commit = "def6789012345..."
artifact_id = "spdlog"
required_by = ["root"]
content_hash = "cafebabe..."
path = null

[[package]]
name = "mylib"
version = "0.1.0"
repository = null
commit = null
artifact_id = "mylib"
required_by = ["root"]
content_hash = null
path = "/home/user/project/libs/mylib"

checksum = "blake3_hash_of_entire_file"
```

## Fields

### `[metadata]`

| Field | Type | Description |
|-------|------|-------------|
| `generated_by` | string | Veld version that generated this lockfile |
| `generated_at` | string | ISO 8601 timestamp |
| `manifest_hash` | string | blake3 hash of the serialized manifest for staleness detection |

### Top-Level

| Field | Type | Description |
|-------|------|-------------|
| `profile_hash` | string | blake3 hash of the active profile config |
| `checksum` | string | blake3 hash of the entire file (excluding this field) for integrity verification |

### `[[package]]`

Each entry represents a resolved dependency:

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Package name |
| `version` | string | Semantic version |
| `repository` | string or null | Git repository URL (null for path deps) |
| `commit` | string or null | 40-character commit SHA (null for path deps) |
| `artifact_id` | string | Unique identifier for the artifact |
| `required_by` | array of string | List of packages that depend on this. `["root"]` means it's a direct dependency. |
| `content_hash` | string or null | Content hash for integrity (null for path deps) |
| `path` | string or null | Absolute filesystem path (for path deps; null for git deps) |

Packages are **sorted by name** for deterministic serialization.

## Integrity Checksum

The lockfile uses a blake3 checksum for tamper detection:

### Write Process

1. Serialize all fields **except** `checksum` to TOML.
2. Compute `blake3::hash()` of the serialized content.
3. Re-serialize with the `checksum` field included.
4. Write to disk.

### Read Process

1. Parse the TOML file.
2. Extract and remove the `checksum` field.
3. Re-serialize without `checksum`.
4. Compute `blake3::hash()` and compare with the stored value.
5. If they differ, return a `LockfileCorrupted` error.

This ensures the lockfile has not been manually edited or corrupted.

## Manifest Hash Staleness Detection

The `manifest_hash` field enables veld to detect when `veld.toml` has changed since the last resolution:

1. On `veld install`, compute `blake3::hash()` of the current manifest (serialized deterministically via BTreeMap).
2. Read the `manifest_hash` from `veld.lock`.
3. If they match and `--force` is not set, skip resolution.
4. If they differ, re-resolve and update the lockfile.

This provides fast-path optimization for unchanged manifests.

## Direct Dependencies

A package is considered a **direct dependency** if `"root"` appears in its `required_by` list.

The `direct_dependencies()` method filters packages accordingly:

```rust
fn direct_dependencies(&self) -> Vec<&LockedPackage> {
    self.packages.iter()
        .filter(|p| p.required_by.contains(&"root".to_string()))
        .collect()
}
```

## Conversion from Dependency Graph

The `Lockfile::from_resolved_graph()` method converts a `DependencyGraph` to a lockfile:

1. Iterate all nodes in the graph.
2. For each node, collect outgoing edges (dependents) to build the `required_by` list.
3. Packages with no dependents get `required_by = ["root"]`.
4. Sort packages by name for deterministic output.

## Package Lookup

Two lookup methods are available:

| Method | Description |
|--------|-------------|
| `find_package(name)` | Linear search by package name |
| `find_package_by_artifact_id(id)` | Linear search by artifact ID |

## Validation

### Profile Validation

The `validate_profile()` method compares the stored `profile_hash` with a computed hash of the current profile. A mismatch indicates the profile has changed since the lockfile was generated.

### Version Validation

The `validate_version()` method checks if the lockfile was generated by the current version of veld by comparing `generated_by` with `SELF_VERSION`.
